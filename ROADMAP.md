# Roadmap

> **Last reviewed:** 2026-10-17 · **Last updated:** 2026-10-17 · **Change list:** minor (As Late As Possible, #122) · **Target:** Microsoft Project (desktop)

ProjectCraft aims for parity with Microsoft Project's scheduling, as its documentation describes it. Each roadmap milestone has a pass/fail checklist; it is reached when every item passes.

## M4 — Microsoft Project XML and CSV in and out ✅ (2026-10-17)
Imports open as a new project, dates recomputed by ProjectCraft's scheduler, with an import report of what was converted or dropped and which tasks' dates differ from the file's.
- [x] Tracer (#97): Open of a Microsoft Project XML file (or `file.import`, or `projectcraft-cli … --import FILE`) makes a new, untitled project of the file's task names, outline levels and durations and the project calendar's working week, scheduled by ProjectCraft, with the import report; the rest of the file is reported as converted, dropped or not yet imported
- [x] Calendars (#99): the project calendar comes in exactly, its weekday working times and its exceptions (non-working, or working with their own times; recurring ones worked out to their days); each other base calendar and each task calendar is a report line
- [x] Task fields (#100): each task's constraint (all of Project's types and their dates; As Late As Possible exactly since #122), deadline, task type and effort-driven setting, and the project's default task type and new-tasks-effort-driven option, come in exactly; priority and leveling delay too since #102; baselines, actuals, % complete, notes, hyperlinks, custom fields, splits and recurring tasks are a Dropped line each
- [x] Links (#98): Microsoft Project XML links of all four types come in with their lags and leads; elapsed lags and durations become the same number of working units (`2ed` is `2d`) and percent lags that share of the predecessor's duration, a report line per lag; links to tasks not in the file, in other projects, to the task itself, repeated, between a summary and its own subtask, or closing a loop are dropped with a line; each task whose Start or Finish as ProjectCraft schedules it differs from the file's is a "Dates differ" line (task, file dates, our dates)
- [x] Resources, assignments and costs (#101): work, material and cost resources come in with their Max Units, standard and overtime rates, cost per use, Accrue At and own calendars (part-time weeks, leave); assignments with their units and work (a material's quantity, a cost resource's amount); task fixed costs; the currency's code, symbol and decimal places, amounts read exactly into its minor units; costs match the file's to the penny
- [x] CSV import (#103): Open of a `.csv` (or `file.import` with format `csv`, or `--import`) makes a new, untitled project named after the file; UTF-8 with or without a BOM, comma or semicolon found from the heading row; `Task Name` required; `Duration`, `Predecessors` (by row), `Resource Names`, `Outline Level`, `Constraint Type` and `Constraint Date`, and `Deadline` read; every other column, and every cell that can't be read, is an import-report line
- [x] Microsoft Project XML export (#102): File › Export › Microsoft Project XML… (or `file.export` with format `mspdi`, or `projectcraft-cli export SOURCE --format mspdi OUT.xml`) writes a copy of everything the project holds, with Unique IDs as UIDs, rows as IDs, and ProjectCraft's computed Start, Finish and slack; export → import → export is byte for byte the same and import → export → import the same project. Export gaps: a material used at a rate (`2 tons/d`) is written as the quantity it uses (the published schema has no rate field); a resource weekday set to the project's own times is written as following the project calendar; an assignment's duration is worked out again from its work and units (within a minute); the column chooser and the assignment-units option are not written
- [x] CSV export (#104): File › Export › CSV… (or `file.export` with format `csv`, or `projectcraft-cli export SOURCE --format csv OUT.csv`) writes the task sheet: ID, Task Name and the shown columns in the column chooser's order with their headings (hidden columns are not written), every cell exactly as the sheet shows it, and an `Outline Level` column when the plan has summary tasks; UTF-8 with a byte order mark, commas, CRLF, RFC 4180 quoting; Task Name and Resource Names cells that start like a spreadsheet formula get an apostrophe in front, which the CSV import takes off. The CSV import now also reads `Fixed Cost`, `Type`, `Effort Driven`, `Priority` and `Leveling Delay`, keeps a quoted name's spaces, takes the currency from the amounts' symbol, and makes a new resource named with an amount a cost resource and with a quantity a material. Export → import gives the same tasks in every column it reads. CSV gaps: Work, Cost, Start and Finish are worked out again, not read (a CSV holds no rates, calendars or constraints; the earliest Start is the project start), so a summary's rolled-up Duration can differ too; a resource's rates and Max Units aren't in a CSV; a lag too small to show (`+0w`) comes back as none; amounts in a currency ProjectCraft doesn't know read as unreadable; with the decimal units format a work resource's units (`0.5`) read as a material's quantity
- [x] Acceptance (#105): parity fixtures in `crates/interchange/tests/fixtures/parity/`, each with the Start and Finish dates Microsoft Project works out written in it and a `.expected` list of the "Dates differ" lines accepted as gaps below (any other difference fails the test, and so does a listed one that stops happening); a fixture made in Microsoft Project, ProjectLibre or GanttProject with invented tasks is added by dropping it and its `.expected` in the folder, with an `ATTRIBUTION.md` row. Three hand-written from Microsoft's published schema and scheduling rules: summaries, all four link types with lags and a lead, every constraint type, a deadline, holidays and a working Saturday morning (dates all match); resources on their own calendars, assignments, each task type and costs (dates all match); and each conversion below that moves dates (five accepted differences; As Late As Possible, the sixth, matches since #122). Every import fixture also round-trips through export. `cargo xtask perf` gates importing a 2,000-task Microsoft Project XML file under 1 s (about 20 ms)

Import gaps, until later work closes them (each is a line in the import report):
- Converted, and the task's dates can differ from the file's: elapsed durations, lags and leveling delays become the same number of working units (`3ed` is `3d`, an elapsed month `1emo` is 30 elapsed days and becomes `1mo`); a task calendar is dropped and the task scheduled on the project calendar; a constraint is held to the day, its time of day left (a start constraint starts at the day's first working minute, a finish constraint ends at its last; reported when that moves the task); a project scheduled from its finish date is scheduled from its start; contours other than flat become flat (a contoured assignment may finish sooner); manually scheduled tasks become auto-scheduled; a task's duration is its longest assignment's (work ÷ units on the resource's calendar), reported when that isn't the file's; a resource calendar based on another base calendar keeps that calendar's week but not its exceptions; work weeks (a different week for part of the year) are not yet imported, the default week is used all year
- Converted, dates unaffected: percent lags become working time from the predecessor's duration; a variable-rate material becomes a fixed quantity; an assignment on rate table B–E is costed at table A; budget resources become ordinary resources; inserted projects come in as ordinary tasks; a deadline is held to the day
- Dropped: base calendars other than the project's and resources', rate tables B–E, rates and availability that change over time, overtime work, assignment delays, fixed-cost accrual at the start or end, the estimated-duration mark (`?`), timephased data
- Dropped until tracking (M3): baselines, actuals, % complete
- Dropped for now: notes, hyperlinks, custom fields, outline codes, resource contact details, task splits, recurring tasks (their occurrences come in as ordinary tasks)
- Read by the published schema, not yet checked against a file saved by Microsoft Project (a file the owner makes in Project with invented tasks settles each): a percent lag's `LinkLag` read as tenths of a percent; `LevelingDelay` read as tenths of a minute, like `LinkLag` (Microsoft's element page shows `3` with the days format for three days); rates read per hour of work (per unit for a material) and every amount as a plain decimal of the currency; an `xs:duration` day (`P1D`) read as 24 hours (Project writes hours, `PT24H0M0S`); the Duration Project writes for a task whose assignments are on different calendars
- CSV: a file with no `Start` or constraint date starts on 1970-01-01, with a line saying so; CSV export writes no constraints (the task sheet has no constraint column) and no calendar
- Not yet: appending or merging into the open project; a CSV column-mapping wizard
